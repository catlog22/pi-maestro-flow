pi-cockpit · Zen 深化设计

STATIC MOCK v2 · 2026-08-12 在 Zen 风格（零边框 · 排版驱动 · 单强调色）下，覆盖全部插件面：teammate（状态全谱 / 输入路由 / 专家模式 / attach）、 todo（收展 / 受阻 / 指派）、goal（预算 / 暂停）、bash_bg、monitor 监督、swarm 汇总，以及 Zen 化的 L3 详情页。 心智模型不变：MISSION / WORK / ACTORS / VITALS，L0–L3 缩放轴。

一切皆行无框无底色，缩进即层级。一行 = 字形柱(2格) + 主体 + 细节 + 遥测 + 时间，全部实体（run/task/agent/job/window）同一语法。
金色预算唯一强调色（暖金）同屏最多 3 处：当前焦点 · 输入路由目标 · 需要人的暂停点。绿只说「好」，红只说「要处理」，其余灰阶。
静默出场段落只在有内容时存在：无任务则无 WORK 段，无参与者则无 ACTORS 段，空闲时终端近乎素文本。出问题时相关行才浮现。
焦点即展开L2 浏览态选中一行，细节在原地展开 1–3 行（缩进灰字），不弹窗；Enter 才进 L3。信息跟着注意力走。
打字优先浏览态不锁输入：直接打字立即回到编辑器。任何 sheet 内 Esc 一步回浏览、再 Esc 回编辑。
排版化 L3详情页不是对话框：无边框 sheet，仅左侧一条金线 + 面包屑，行语法与 L1 完全一致，学一次到处适用。
视口纪律常驻 UI 全部锚定在编辑器上方的底部栈（视口内，只走差分更新）；流区上方零变化行，滚离视口的行立即定格。这是对 pi-tui 置顶 bug（fullRender 分支）的结构性规避，详见第 08 节。

02teammate 面深化

  • 状态全谱一行说完：⠋ reviewer-1 — review diff · ↑8k/↓2k · 1m02。retry 显示 ↻ 第2次，stalled 显示 ~ 停滞 5m 并自动上浮到段首（问题行优先于运行行）。
  • 输入路由是金色契约：浏览态选中 agent 按 m（或 sheet 内选「发消息」），编辑器前缀变 @rev-1 ❯——金色前缀 = 此刻打字发给谁。Esc 清除回主会话。复用现有 cockpit:input-target 事件与 routeAgentInput（steer/follow_up 两种投递已支持）。
  • 专家模式即缩进：☆ leader 一行，子 agent 缩进两格挂其下；蜂群（swarm）workers 同理，只显 迭代 3/8 · best 0.87 汇总，Enter 进 sheet 看全体。
  • attach / 进度树 → L3 sheet：agent sheet 内 a attach、enter 查看线程（复用 window-thread-view），不再是独立 overlay 体系。
  • ambient 键保留：空编辑器 ←/→ 循环 agent、Shift+↑↓ 滚动 roster（现有 ambient.ts 逻辑，Zen 下不变）。

03todo 面深化

  • 默认极简：WORK 段 = 1 行 chain + 最多 3 行任务（进行中 > 受阻 > 下一个待办），其余折进 … 还有 2 项。
  • Alt+T 展开：原地展开全部任务（非弹窗），再按收回——映射现有 cockpit:toggle-todo 事件。
  • 受阻要说原因：! 清理 allow-list — 等 task 02，选中展开显示 blocked-by 链；解阻后该行自动褪回灰阶。
  • 指派即链接：@rev-1 是到 ACTORS 的引用，task sheet 内 Enter 跳到该 agent 的 sheet（同一面包屑体系 work › task 02 → actors › rev-1）。
  • 完成不喧哗：done 行灰字加删除线，超过 3 条折叠为 ✓ 2 done 计数——Zen 只为「还没完成的事」花墨水。

05工具行与流内显示（quiet 模式）

对话流由 Pi 原生渲染，Zen 不重画它——quiet 模式把 7 个内置工具（read / bash / edit / write / grep / find / ls）压缩为与 widget 区同语法的单行，思考块折叠为一行计时。这是「一切皆行」延伸进流内的方式。

工具状态流内显示说明
运行中⋯ bash npm test -- jwt · 12s生命周期字形 ⋯ → ✓/✗；耗时实时累计——但仅当该行仍是最后活动行，被新输出顶上去后立即定格（滚离即定格，防置顶）
成功✓ edit src/auth/jwt.ts · +18 −4结果摘要跟在参数后（行数 / diff 数 / 匹配数）
失败✗ bash npm test · exit 1
  FAIL rotate.spec.ts — expected …		失败额外给一行红色首错，不淹没在灰阶里
思考块thinking · 8.4s折叠计时行；运行中显示 spinner + 实时秒数（thinking-timer）
字形集check ✓/✗/⋯ 或 dot ●/○/◌quietSymbols 配置；配色族 toolPalette（classic/family/readwrite/search/mono）

约束（诚实声明）：内置工具的原生渲染只能整体替换、不能逐行接管，因此 L2 浏览态不进入流区——工具详情的展开/收起仍由 Pi 处理（ctrl+o 展开工具输出）。

08渲染纪律（防「回弹顶部」）

pi-tui doRender() 存在上游缺陷：当首个变化行位于视口上方时无条件 fullRender(true)（清屏 + 光标 home + 清 scrollback）= 整页置顶。 触发条件 = 视口上方存在频繁变化的行（每秒耗时 / spinner 是典型元凶，teammate 进度树曾踩中， 见 TIP-20260725-pi-viewport-jump-fullredraw）。Zen 用四条纪律做结构性规避：

纪律规则对应设计元素
① 布局不变量常驻 UI 只存在于 aboveEditor/belowEditor 栈与 footer（永在视口内，差分更新）；setHeader 只放一次性静态内容；「顶部横幅」形态仅允许出现在 opt-in fullscreen 交替屏模式（交替屏无 scrollback 可清）MISSION 是底部栈第一行而非流顶横幅；栈序 = MISSION → WORK → ACTORS → ALERT → 窗口条 → 编辑器（对齐现有 detail → Todo → session bar → editor 不变量）
② 滚离即定格流内任何带实时计时/spinner 的行，只在其仍是最后活动行时更新；被新输出推离后立即冻结为最终值，此后一个字节都不再变quiet 工具行的运行秒数、thinking 计时行（thinking-timer 已实现此行为，工具行照抄）
③ 滞回与高度预算底部栈高度变化不触发置顶，但会推挤编辑器；段落消失先降为 1 行摘要、延迟一拍再移除；展开（Alt+T / L2 原地展开）在固定 N 行窗口内进行，超出折叠为 … n more静默出场的段落增删、任务展开、L2 选中展开
④ 双保险运行时挂 viewport-stability.ts 补丁（镜像上游修复，widget 安装时已调用）；staticMode 一键冻结全部 tick；usage 计数 500ms 节流；根治补丁落在用户 fork 的 tui.ts（TIP 内已验证 693/693）全局

这也是 Zen 相对另两案的结构优势：无 dock、不包装 renderer，全部复用 stack-widget 已验证的底部栈管线—— 方案 C（全高左列布满 spinner）最贴近触发形态，建议仅作为 fullscreen 模式下的形态保留。

  • 降级阶梯：Zen 本就无 dock，宽窄屏同构；极窄时 WORK/ACTORS 各折叠为 1 行摘要；TERM=dumb 只剩 footer。
  • 接口依据：全部行走 setWidget(aboveEditor)（无需 split-pane）；sheet 走 ctx.ui.custom({overlay:true})；前缀走现有 input-target 事件；浏览态复用 onTerminalInput 钩子——Zen 是三案中实现增量最小的（不动渲染器包装）。
  • 协议依赖：chain 有名步骤与 run attempt 仍需快照 v2；v1 下 chain 行退化为 step 2/4 计数（其余全部可跑）。
  • 金色预算的实现：投影层做一次「accent 配额」裁决——焦点行、输入目标、暂停点按优先级取前 3，其余强制降灰，防止多产者把界面染黄。
