STATIC MOCK · 2026-08-12 同一统一心智模型（MISSION / WORK / ACTORS / VITALS，L0–L3 缩放轴）、同一场景（auth 刷新令牌修复 · Run R3 · reviewer-1 + npm test）， 三种完全不同的视觉与布局哲学。信息架构不变，变的是密度、装饰量与空间组织。

哲学
全信息在场，边框即结构。k9s / mission-control 血统：MISSION 是顶部横贯条，dock 是三块带框面板，运行行有高亮泳道。给重度并发用户——扫一眼就要看到所有仪表。
取舍
密度最高、字号最小；边框消耗 2 列宽度；窄屏降级最激进（面板逐块折叠为单行）。
适用
≥140 列宽屏 · 多 agent / swarm 并发 · 监督者角色（monitor 窗口常驻）。

三案对比（同一心智模型，不同投影）

维度A · OPS 密度优先B · Zen 极简C · 时间轴脊柱
MISSION 位置顶部横贯条（常驻整行）流顶部一段文字顶部横幅 + 状态 pill
WORK 呈现右侧面板：横向 chain + 进度条编辑器上方 1 行 chain + 3 行任务左侧垂直 rail，step 即节点
ACTORS 呈现独立面板，kind 列对齐单行滚动摘要，有动静才出现挂在所属 step 节点下（acting here）
占用列宽右 dock ~42 列0（无 dock）左 rail ~54 列
视觉装饰边框 + 底色 + 泳道，最重零边框，单强调色，最轻节点/连线 + 圆角卡片，居中
L2 浏览态面板内选行选中即临时展开该段沿时间轴上下移动，节点整体高亮
窄屏降级面板逐块折叠为单行天然适配（本就无 dock）rail 折叠为顶部横向 chain 条
实现增量（相对现 dock）小：section→panel 包框小：widget 通道复用中：split-pane 需支持左侧停靠 + 节点分组渲染
数据依赖协议 v1 可跑（计数即可）协议 v1 可跑强依赖 v2（有名 step 序列 + run 归属）

建议：默认风格取 A 与 B 之间的中间档（即上一版 pi-cockpit-unified.html 的形态），把 A/B/C 作为 sidebar.style = "ops" | "zen" | "rail" 主题化配置暴露——三案共享同一投影数据与浏览态代码，仅替换 render 层，符合现有 sidebar-render.ts 纯函数边界。
