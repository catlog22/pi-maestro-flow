01为什么收敛：旧区块 → 新三层映射

旧侧栏按「数据来源」切分（Workflow / Goal / Tasks / Agents / Jobs / Swarm 六个平行段），用户需要自己在脑中拼装因果；新结构按「用户在任何时刻会问的三个问题」切分，且与目标架构 Session → Run → Participant 一一对应，界面即数据模型。

旧区块（来源导向）去向理由
Workflow（会话行 + 进度 + gates）MISSION（会话/gates）+ WORK（chain/run）会话身份与执行进度是两个问题，拆开
Goal（objective / 预算 / 迭代）MISSIONGoal 的 objective 与 Session objective 同为「在做什么」，预算并入详情页
Tasks（Todo 平铺）WORK · 挂在当前 step 之下任务从属于当前 Run/step，不是独立宇宙；assignee 直接连到 ACTORS
Agents / Jobs / Swarm workersACTORS · 统一行 schema都是 participant：状态字形 · 类型 · 名称 · 正在做 · 遥测 · 时长，六列同构
Swarm（objective / 迭代 / best）MISSION 尾注 + ACTORS worker 行swarm 只是执行策略，不值得一等区块
Footer 双行VITALS · 保持不变唯一常驻资源视图，任何降级都保留

02统一交互轴：一条路径代替一堆入口

  • 单一缩放语义：L0 扫视（永远在场）→ L1 停靠摘要 → Tab 进入 L2 浏览态 → Enter 进入 L3 详情 → Esc 逐级返回。任何信息都在这条轴上，不再需要记「哪个面板用哪个键」。
  • 统一详情壳：session / run / task / agent / job / window / 设置共用同一 overlay 外壳 —— 面包屑（cockpit › actors › reviewer-1）+ 字段区 + 实时尾巴 + 底部按键行。旧的 Alt+J / agent overlay / session detail 全部变成同一壳的不同内容页。
  • 按键规约不变量：Esc 返回/关闭（脏状态二次确认）、Enter 深入/确认、Tab 切段/切范围、Space 开关、Ctrl+S 保存、直接打字即筛选。全部 TUI 面共享，与现有 /maestro-settings 规约一致。
  • 快捷键降级为加速器：Alt+J / Alt+W / Alt+M 保留为直达位（跳到 L3 对应页），但不再是唯一入口；hint line 随焦点上下文切换，所见即所得。

03降级阶梯与 TUI 可行性

  • 宽屏（≥72+32 列）：右侧 dock，三段广度优先——先保证每段摘要行，再给明细行；高度不足时按 MISSION > WORK > ACTORS 保留，隐藏量以「… n more」如实标注。
  • 窄屏：dock 消失，压缩为编辑器上方三行 widget（本页可切换演示）——每段一行摘要，语义与 dock 完全同构，心智不切换。
  • 极窄 / TERM=dumb：只剩 VITALS footer 单行。
  • 无动画依赖：选中态用 ▸ 前缀 + 背景色，运行态用 braille spinner 帧，均为现有渲染器已验证的手段；不引入 hover/focus 等终端不存在的概念。
  • 数据契约不变：仍消费 maestro:ui-snapshot / teammate 事件 / todo-state / bash_bg，仅改投影层（sidebar-render 的 section 组织）与导航层（browse 模式已有 scrollStart / focusedRowId 基础）。
