# Teammate runtime error 的非 rejectAndPublish 路径

## 陷阱(pitfall)

当 pi-subprocess 子进程在运行时记录错误消息时,该错误会被放进 `result.messages`,**不一定走 `rejectAndPublish` 路径**。这会导致:

- task 可能以 `exitCode=1` 完成,但仍经过**正常的 `publishResult` 路径**(有 `publicationId`)
- 调用方若只检查 `exitCode` 或只监听 reject,会**漏掉这类错误**
- 错误消息混在 `result.messages` 里,需显式读取才能发现

## 复现条件

- teammate task 运行中遇到 runtime error(非 reject 触发)
- 子进程未 crash,而是把错误记进 messages 后正常退出

## 正确处理

消费 teammate 结果时,**不能只看 exitCode**;必须同时扫描 `result.messages` 中的 runtime error,否则会误判 task 成功。
