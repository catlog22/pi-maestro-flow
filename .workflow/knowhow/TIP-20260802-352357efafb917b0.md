# 模型 failover 注入时机：旧 followUp 队列 vs 新 agent_settled triggerTurn

## 现象（症状）
主模型中途失败（如 `Stream ended without finish_reason`）时，TUI 中反复显示一条排队消息
`Follow-up: The previous model failed with a transient network or provider error, ...`
一直不消失，也从未真正注入对话。用户猜测"agent 没有中断所以没有注入"——判断正确。

## 根因
1. 该文案是旧版 `FAILOVER_RETRY_PROMPT`（git 2857e95c 及更早）：
   `pi.sendUserMessage(FAILOVER_RETRY_PROMPT, { deliverAs: "followUp" })` 在 **agent_end** 事件里调用。
2. pi-core 语义（pi-agent-core/dist/agent.js）：follow-up 消息"run only after the agent would otherwise stop"，
   即只有 agent 将要停止时才会被消费注入；排队期间 TUI 以 `Follow-up: ...` 前缀显示在 pending messages 区。
3. 时机错位：`agent_end` 触发时 pi-core 可能正在原生重试、或已自行"continuing the turn with 另一模型"继续本 turn。
   agent 从未到达停止点 → follow-up 一直滞留队列（一直显示、不注入）；只有中断 agent 才可能消费。

## 当前设计（HEAD，正确做法）
- 注入点移到 **agent_settled**（agent 完全落定、原生重试/压缩/队列排空之后），
  用 `pi.sendMessage({ customType: "maestro-model-failover", content: recoveryPrompt(recoveryId), display: false, details }, { triggerTurn: true })`。
- `triggerTurn: true` 且非 streaming 时，sendCustomMessage 直接走 `_runAgentPrompt` 立即启动隐藏自定义 turn
  （不进 follow-up 队列、不显示 Follow-up: 前缀）；仍 streaming 时退化为 steer 队列（显示 Steering:，turn 结束后注入，不会滞留）。
- 新文案明确"exhausted its native retries"，与 agent_settled 的触发时机一致；内容带 `[maestro-model-failover:<recoveryId>]` 恢复标记，
  before_agent_start 用它消费手令并接管 acquisition。

## 陷阱（pitfall）
- 扩展代码在 pi 进程启动时加载，文件变更**不会热重载**；旧进程内存里仍是旧逻辑。
  看到旧文案/旧行为先检查 pi 进程启动时间，执行 `/reload` 或重启进程再排查。
- 扩展内给 agent 排队消息时：`deliverAs: "followUp"` = 只在 agent 停止时注入（易滞留）；
  `deliverAs: "steer"` = turn 结束后注入；`triggerTurn: true` = 立即启动新 turn（无需依赖 agent 停止）。
  需要"失败后立即重试/续跑"的场景应选 triggerTurn 或 steer，不要选 followUp。
