# Teammates Mailbox 多 Agent 审查与 P0/P1/M 硬化记录

## 审查方法
4 个只读 analyst agent 并行审查（正确性/生命周期、安全/数据完整性、架构/API 契约、测试覆盖），关键发现经本地 grep/sed 抽查复现，多维度交叉确认。聚焦测试 118→135 用例全绿。

## 已修复（源码 8 文件 + extension 接线 + 回归测试）

### P0 数据丢失/契约破坏
- **accepted 状态机悬空**：`service.acknowledge`/`runGC` 无生产调用方导致消息永久滞留 accepted 并耗尽 512 配额、投递静默失败。修复：consumer dispatch 成功即自动 `apply`（ACCEPTED→APPLIED）；`replayAcceptedToReady` 启动重放崩溃残留；失败重试上限 `MAX_DISPATCH_RETRIES=5` 转 dead；MailboxHost 周期 GC 定时器（10min 默认，`gcIntervalMs` 可注入）。
- **per-workspace 隔离失效**：MailboxHost 在激活期构造时 `baseCwd=""`，workspaceId 恒为 0×64。修复：改为 session_start/session_compact 按真实 cwd 惰性绑定（`rebindMailboxHostForSession`），跨会话/跨进程混流根除。
- **ISS-20260803-003 生命周期栅栏**：service `#startPromise`+`#stopped` 启动屏障（stop 在 start 初始化期间到达则续体 bail，stop 永远 await 在途 start）；rollout `setMode` 异步化且降级先 await stopConsumer 再发布模式；consumer 各 await 后复验 `#stopped`（stop 后不再发起新 claim，stop 为干净 drain）；session_shutdown 在 teardown 前 stop mailbox。

### P1 安全
- **信封完整性**：`readEnvelope/readStateRecord` 读前 `lstat` 预检（拒 symlink/非普通/超限）+ 强制 `verifyEnvelopeHash`；篡改/损坏信封在 consumer 侧 dead-letter。
- **标识符 sanitize**：workspaceId/senderId/recipientCorrelationId 按 `SAFE_ID_PATTERN`/`CORRELATION_ID_PATTERN` 校验（路径穿越面关闭）；`acknowledge` 校验 messageId 格式。
- **shadow 契约**：`service.start(startConsumer=false)` 仅建目录不启动 consumer。

### M 级
- **租约绑定**：`currentLeaseEpoch/Nonce` 增加 recipient 参数并绑定 activeRuns 中真实 SessionLease（handoff 后 epoch/nonce 旋转 → 旧信封 revalidate 转 dead）。
- **单一模式源**：`host.mode` 改 getter 代理 rollout（运行时 setMode 立即反映）。
- **去重 + seen GC**：dedup 键改为 requestId ?? correlationId（v1 registry taskId 场景生效，无 requestId 不写 seen）；seen 文件名 sha256 哈希化防路径逃逸；GC 按 TTL_RECEIPT_MS 清扫 seen 目录。
- **投递语义**：`deliverLocalAgentMessage` 改 async，enqueue 失败返回 delivered:false（不再谎报成功）；移除 enqueue 回调与 inject 双重记账（重复 inbox/事件）。
