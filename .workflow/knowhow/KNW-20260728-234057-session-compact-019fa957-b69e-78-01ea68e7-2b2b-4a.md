## Decisions
- **Main Agent failover is explicit-config driven**: Do not choose arbitrary authenticated models; users define ordered chains.
- **Main Agent keeps Pi core retry ownership**: The extension switches models during `agent_end` before Pi continuation, while Pi remains responsible for its retry loop.
- **Teammate owns child retry/failover**: Child Pi auto-retry is disabled to avoid multiplying retry budgets.
- **Breaker key is exact `provider/model`**: Provider-only or model-ID-only health would conflate endpoints.
- **Failure counts once per exhausted model per dispatch**: Initial attempt plus five retries contributes one breaker failure; half-open receives one attempt.
- **Permanent errors do not retry or fallback**: 401/403, invalid model, context overflow, and schema/validation errors do not poison health.
- **Root proxy is routing authority**: Child model catalogs may be stale or narrower than root catalogs.
- **Failover model selection is session-sticky**: Do not automatically switch back after cooldown because `pi.setModel()` persists selection and an automatic restoration could overwrite a later user choice.
- **TUI filtering is explicit**: `/` enters filter mode; ordinary letter keys remain available for actions.
