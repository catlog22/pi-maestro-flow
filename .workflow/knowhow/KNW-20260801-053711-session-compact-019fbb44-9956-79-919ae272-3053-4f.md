## Decisions
- **采用 per-owner 文件协议，不用共享可写 registry**：`~/.pi/teammate/workspaces/<workspace-hash>/runtime/` 下每个进程只原子替换自己的 owner 文件，避免全局 registry 读改写竞争与集中锁；owner-id 用随机 UUID + incarnation nonce（不用 PID 作为唯一身份）。
- **远端 agent 保持只读镜像**：`WorkspaceAgentSnapshot` 不插入 `state.activeRuns`；生命周期/stdin 控制权只在原始 owner 进程；首期远端写路径仅 `/monitor` 显式绑定（mailbox whitelist `steer|follow_up`），不开放跨会话 abort。
- **workspace 身份 = 规范化绝对 cwd 的 SHA-256**（文件内同时保存规范化路径并在读取时校验）；不同 cwd 完全隔离。
- **Target 解析统一但保留来源边界**：local+remote 统一支持 cid/唯一前缀/name/`name#id-prefix`；同名/前缀冲突返回 ambiguous，不做 last-wins。
- **威胁边界**：同 OS 用户 peer 进程为可信主体；磁盘 JSON 解析按不可信、有界输入处理；静态 symlink 拒绝已覆盖，但 Node 跨平台 API 无法保证目录级 `openat` 原子防换，TOCTOU 目录替换不在防护承诺内。
- **child proxy 保持 root tree 作用域**：teammate target 先在本地 `activeRuns/progress/recentlySettled` 解析并规范化为 exact cid，远端-only target 明确拒绝。
- **monitor engine generation 护栏**：`engine.abortController` 贯穿 engineTick 与 mailbox wait，`/monitor exit` 后旧 tick 不得再发送/记录干预。
- **handoff owner identity 复用**：同 cwd 的 session_start 若 `existing.identity.workspaceId === workspaceIdForCwd(cwd)` 则 markDirty+publishNow+refresh，不重建 owner，避免远端 binding 失效。
- **mailbox retention 纳入 publish 周期**：`cleanupWorkspacePeerMailboxes` 随 publish 执行；stale owner 清理同时删除其 command 目录。
