# 安装文档深度核查修正记录

## 背景

对 `/install` 命令的 5 个 AI 安装文档做深度核查，发现 4 个文档存在事实性错误（臆测的配置结构）。逐项核实源码后修正。

## 核查发现与修正

### 1. INIT-SETUP.md（严重错误，已重写）

**错误**：
- `auth.json` 结构写错：臆造为 `{provider: {apiKey: "sk-..."}}`。
- `model-failover.json` 结构写错：臆造为 `{version, routes:[{model, fallbacks}]}`。

**真实结构**（核实源码 + 实际文件）：
- `auth.json`：`{provider: {type: "api_key"|"oauth", key|access: "..."}}`。`type:"api_key"` 凭证字段是 `key`；`type:"oauth"` 是 `access`。核实于本机 `~/.pi/agent/auth.json`（kimi-coding/openrouter 条目）。
- `model-failover.json`：`{enabled: boolean, fallbackModels: Record<model, fallback[]>, defaultFallbackModels?: []}`。无 `version`、无 `routes`。核实于 `src/providers/model-failover.ts` ModelFailoverConfig 接口 + 本机 `.pi/model-failover.json`。

### 2. MCP-SETUP.md（严重错误，已重写）

**错误**：
- 配置路径写错为单一 `~/.pi/agent/mcp.json`，且键名写为 `servers`。
- ServerEntry 结构臆造。

**真实结构**（核实 `src/mcp/config.ts`）：
- 多源发现（4 源）：`shared-global`（`~/.config/mcp/mcp.json`）→ `pi-global`（`~/.pi/agent/mcp.json`）→ `shared-project`（`.mcp.json`）→ `pi-project`（`.pi/mcp.json`）。Pi 写入优先 pi-global。
- 键名是 `mcpServers`（非 `servers`）。结构 `{mcpServers: Record<name, ServerEntry>, imports?: ImportKind[], settings?}`。
- ServerEntry：stdio 用 `command/args/env/cwd`；HTTP 用 `url/headers`；`auth: "oauth"|"bearer"|false`；OAuth 走 `/mcp auth <name>` 不手填 token。
- `mcp-cache.json` 是运行时凭证缓存，非配置源——不能用于探测。

### 3. SMART-SEARCH-SETUP.md（路径错误，已重写）

**错误**：配置路径写为 `~/.maestro/cli-tools.json`（那是 Maestro delegate CLI 的配置，与 smart_search 无关）。

**真实结构**（核实 `src/tools/smart-search-config.ts`）：
- 路径：Windows `%LOCALAPPDATA%/smart-search/config.json`；其他 `~/.config/smart-search/config.json`；`SMART_SEARCH_CONFIG_DIR` 覆盖。
- 扁平 env 风格键：`TAVILY_API_KEY` / `EXA_API_KEY` / `CONTEXT7_API_KEY` / `JINA_API_KEY` / `FIRECRAWL_API_KEY` / `ZHIPU_API_KEY` / `OPENAI_COMPATIBLE_API_KEY` 等。
- 最低档案：main_search + docs_search + web_fetch 各至少一 provider。
- `/smart-search` 命令开设置 TUI；route 诊断是 AI 工具 `smart_search {mode:"route"}`，非 CLI。

### 4. TEAMMATE-MODELS-SETUP.md（版本 + taskType 错误，已修正）

**错误**：
- 只写 legacy v2 格式，未提现代 v3。
- taskType 列表多了 `verification`。

**真实结构**（核实 `pi-maestro-teammate/src/models/model-routing.ts`）：
- v1/v2 legacy 仍可用（自动归一化）；v3 是现代格式（项目用 `{version:3, activeProfile, applyOverrides, overrides}`）。
- 全局配置 `~/.pi/agent/teammate-models.json`（含 profiles），项目 `.pi/teammate-models.json`（覆盖）。
- `assertKnownKeys` 仅允许 `mappings/fallbackMappings/thinkingLevels/roleMappings/typeMeta`。
- 内置 `TEAMMATE_TASK_TYPES` 是 7 个：explore/analysis/debug/planning/development/review/testing。`verification` 是 Goal 质量门 taskType，非 teammate 内置路由。

### 5. COMPUTER-USE-WEIGHTS-SETUP.md（正确，无需改）

之前会话已验证：官方 .pt SHA-256、ultralytics export、ONNX SHA-256、验证命令均核实过。

## install-items.ts probeInstallStatus 同步修正

- `init`：auth 探测改为检查 `type` + `key`/`access` 字段（原检查 `apiKey`/`token` 错误）。
- `teammate-models`：同时检查项目 + 全局路径；兼容 v2 `mappings` 和 v3 `overrides.mappings`/`profiles`。
- `smart-search`：改为探测正确的 smart-search config.json，检查至少 3 个 provider key 满足最低档案（原探测 cli-tools.json 完全错误）。
- `mcp`：改为多源探测 `mcpServers` 非空（4 个候选路径），原探测 mcp-cache.json 是凭证缓存非配置。

## 教训

**文档里的每个配置结构、路径、字段名都必须从源码或实际文件核实，不得从命令名或类比臆测**。本次 4 个文档的错误都是因为：
- auth.json：从"API key 配置"类比臆造 `{apiKey}`
- model-failover.json：从"路由"概念臆造 `routes` 数组
- mcp.json：从单一路径臆造，忽略多源发现
- smart-search：把 Maestro delegate CLI 的 cli-tools.json 误当 smart-search 配置
- teammate-models：没查 taskType 权威清单，多列了 verification
